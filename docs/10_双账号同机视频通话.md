# 同机双账号：电脑登主号、和机器人视频通话（实验性）

> 状态：**技术可行，但需要人工配置两步，且相机行为要实测**。本文是操作手册 + 验证清单，
> 不是"一键开启"。失败请按「回滚」回到「手机主号 + 电脑小号」的现有可用方案。

## 目标

- QQ 主号（你）登录在**电脑**上，用电脑和机器人（小号）视频通话
- 机器人仍然跑在这台电脑上（PMHQ 注入的另一套 QQ 客户端）

```
┌─────────────── 同一台 Windows ─────────────────┐
│  QQ 客户端 A（主号·你）   QQ 客户端 B（小号·她） │
│  mic=实体麦克风            mic=CABLE Output      │
│  out=耳机                  out=扬声器(Senary)    │
│  cam=实体摄像头            cam=CameraEmulator    │
└─────────────────────────────────────────────────┘
        ↑ 语音/视频                      ↑ 环回录音 + TTS 推流
```

## 为什么需要两套 QQ

机器人占用了 `C:\Program Files\Tencent\QQNT\QQ.exe`（PMHQ 注入）。主号要另起一个客户端：

- 首选：用另一套安装 `C:\qq-bot\napcat\QQ.exe`（NapCat 自带 9.9.33），**只当普通客户端用，不注入**
- 两套 exe 路径不同，单实例锁通常按安装/数据目录区分，所以有机会共存
- 若仍冲突：用「复制 QQ 到独立目录 + 独立数据目录」，或第二个 Windows 用户会话（更重，不推荐）

## 第一步：验证双实例能共存

1. 先确认机器人正常（`logs/llbot.log` 有登录成功、AstrBot 6199 已连接）
2. 跑 `scripts/start-main-qq.ps1`（用另一套安装启动主号客户端）
3. 检查：
   - 主号客户端能正常登录、机器人**不掉线**
   - 任务管理器里两个 QQ.exe 来自不同路径
4. 冲突（互相顶号/机器人掉线）→ 停止，回滚，改用手机方案

## 第二步：音频路由（最关键）

Windows 11（26200 已确认支持）可以**按应用**指定输入输出设备。
打开设置：`scripts/audio_route_help.ps1` 会直接跳到「应用音量和设备首选项」。

| 应用 | 输入（麦克风） | 输出（扬声器） | 作用 |
|---|---|---|---|
| QQ 客户端 A（主号，`napcat\QQ.exe`） | 实体麦克风 | 你的耳机 | 你说话给她听；你听她说话 |
| QQ 客户端 B（小号，`Program Files\...\QQ.exe`） | `CABLE Output (VB-Audio)` | 扬声器 `Senary Audio` | 她的 TTS 进 QQ；`call_loop` 从扬声器环回听你 |

为什么这样能成立：

- 你 → 她：主号麦克风收音 → 经 QQ → 小号客户端播放到「扬声器」→ `call_loop` 环回录音 → ASR
- 她 → 你：TTS 写入 `CABLE Input` → 小号麦克风（`CABLE Output`）→ 经 QQ → 主号客户端输出到耳机
- 她自己听不到自己：小号输出到扬声器只包含"你的声音"，她的 TTS 走 CABLE 不进环回

**注意**：设置页里按 exe 路径区分两个 QQ；如果列表里只出现一个，把两个客户端都开起来再刷新。

## 第三步：摄像头

- 小号客户端选 `CameraEmulator`（她的形象）
- 主号客户端选实体摄像头（你的脸）
- 前提：实体摄像头要**重新启用**（`scripts/restore-camera.bat` 那类操作；项目里对应 `Enable-PnpDevice`）
- 已知风险：QQ 的已知 bug 是"选了 CameraEmulator 仍抓实体摄像头"。
  - 若出现：小号画面变成你的脸 → 退化为「小号不开视频，只语音 + 文字」，主号仍可发视频给她
  - 这个退化不影响通话本身，只是她那边不露脸

## 验证清单

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 双实例 | 两个 QQ.exe 路径不同、同时在线 |
| 2 | 路由 | 小号输出 = 扬声器；主号输出 = 耳机；小号输入 = CABLE Output |
| 3 | 通话接通 | `logs/call_agent.log` 出现「视频来电 -> 已点击接听」 |
| 4 | 你听她 | 主号客户端能听到她的声音（音色 = 龙菲菲/克隆音） |
| 5 | 她听你 | `logs/call_loop.log` 出现「你：…」识别文本 |
| 6 | 她看你 | 主号发视频后，她说「看看我」能看到你的脸（需视觉功能） |
| 7 | 她露脸 | 主号画面里显示 CameraEmulator 的形象；若显示你自己 → 退化为不开小号视频 |

## 回滚

1. 关闭主号客户端（另一套 QQ）
2. 把两套 QQ 的音频设备恢复为默认
3. 确认机器人仍在：`logs` 里 6199 连接、TTS 9880 正常
4. 手机主号重新登录（原方案）

## 风险与限制

- 双实例可能被 QQ 客户端限制；失败只是"不能同机"，不影响现有可用方案
- 两客户端 + ASR/TTS 同机，CPU/GPU 占用会上升；视频通话时留意风扇
- 同 IP 双账号通话是正常用法，但**别互相顶号**（两个不同账号本身不会）
- 本文不改 `docs/07_发布状态.md` 里「QQ 视频链路未通过验收」的结论：这里只是提供一种
  单机双客户端的配置方式，相机行为仍需真机验证
