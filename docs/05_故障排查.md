# 按症状排查

| 现象 | 先查 | 再查 |
|---|---|---|
| 安装脚本找不到 Python | `python --version`，确认不是 Windows 商店占位符 | Python 3.12+ 是否加入 PATH |
| 下载始终失败 | JSON 中具体文件、网络、预期 SHA256 | 文件放置位置；`.part` 可续传，不能直接改名冒充成功 |
| PyPI 包下载极慢 | 保留安装目录，先停止当前安装 | 运行 `Run-device-test-mirror.cmd` 临时使用清华 PyPI 镜像；不要同时运行两个安装器 |
| pip 报 `ReadTimeoutError` | 确认该次安装已经退出，保留缓存和虚拟环境 | 用镜像入口重试；设备测试入口默认读取超时 120 秒、连接重试 10 次，仅作用于本次进程，保留已有环境变量设置 |
| 下载源码或模型报 `CERTIFICATE_VERIFY_FAILED` | 更新项目下载器并确认已安装 `certifi` | 下载器同时使用系统证书和 Mozilla 根证书；若仍失败，检查系统时间和网络证书链，不关闭 TLS 或主机名校验 |
| 硬件报告 JSON 出现中文乱码 | 使用包含 UTF-8 读取修复的安装脚本 | Windows PowerShell 5.1 需显式按 UTF-8 读取报告 |
| 启动报端口占用 | 是否已有安装在运行 | 用另一组完整配置或人工停止原实例；安装器不会代杀 |
| 没有 QQ 回复 | 客户端是否登录、OneBot 两端是否连接 | AstrBot 提供商、人设、白名单和管理员配置 |
| 接通但听不到人 | call_loop 心跳、输入峰值是否始终为零 | Windows/QQ 是否静音；QQ 播放端点是否与实际监听一致 |
| 她说话但对方听不见 | TTS 输出的虚拟播放端点 | QQ 麦克风是否选虚拟录音端点 |
| 重启后通话没有回复声音 | QQ 通话窗口麦克风旁的小箭头 | 重新确认 CABLE Output 已勾选；配置文件不会自动修改 QQ 设备选择 |
| 日志显示生成回复，随后 IndexError | 是否仍使用旧版 call_loop | 更新包含空音频保护的版本；新版会记录未播放或播放失败并继续监听 |
| 语音偶发变文字 | 本地合成日志、音频长度检查 | 自己账号的云端克隆提供商是否配置 |
| 画面黑屏 | CameraEmulator 驱动、QQ 摄像头选择 | 渲染进程、共享内存及 UDP 口型端口 |
| 画面是 CameraEmulator 默认占位图 | 运行 `CameraEmulator.exe` 是否报 `Saving the layout failed: 0x80070005` | `%ProgramData%\CameraEmulator` 是否对 Users 只读；`Global\CameraEmulatorScreen` 是否存在（Local 段摄像头服务读不到） |
| QQ 里选了 CameraEmulator 仍显示实体镜头 | 设备管理器中是否还有可用的实体摄像头 | 禁用实体摄像头后，QQ 只能使用虚拟摄像头（见下节回退方式） |
| 图在但表情发不出 | `assets/stickers/index.json` 文件引用 | 目标会话与 AstrBot 平台状态 |
| B 站巡检不启动 | `features.bilibili`、master 三项 | 自己的登录态、任务/额度配置 |
| 重复语音回复 | AstrBot 内置 TTS 是否关闭 | voice_picker 是否重复安装 |
| verify 阶段 6 失败 | 是否完成真实测试并填记录 | 不能用旧机器结果或虚构数据补空项 |

设备测试的状态和安装输出位于 `data/device-setup.json`、`data/device-setup.log`；业务日志保存在当前安装的 `logs`。新版设备测试日志包含子安装进程的标准输出和错误输出。反馈问题时提供脚本名、版本、脱敏错误和复现步骤；不要上传整份运行目录或含用户名、路径等信息的原始日志。
预览版的 `avatar_server.py` 和旧版 `avatar.py` 是实验/兼容路径，不是默认动态形象路径。

## 摄像头只显示占位图 / QQ 仍用实体镜头

### 1. 占位图：先看 CameraEmulator 是否真的在工作

手动运行一次，观察输出：

```powershell
& "$env:ProgramFiles\OhWhale\CameraEmulator-0.1.0a1\CameraEmulator.exe" --layout fit <你的图.png>
```

- 报 `Saving the layout failed: 0x80070005`：`%ProgramData%\CameraEmulator` 权限不足，
  `CameraEmulator.exe` 会在保存布局这一步退出，图像根本不会发布。修复：

  ```powershell
  icacls "$env:ProgramData\CameraEmulator" /grant '*S-1-5-32-545:(OI)(CI)M'
  ```

- 提示 `Image published to ...`：图像已发布。此时摄像头源会**每帧重新读取**
  `%ProgramData%\CameraEmulator\image.png`，所以可以用覆盖该文件的方式送动态画面。

### 2. 共享内存为什么有时无效

`scripts/avatar_live.py` 会优先创建 `Global\CameraEmulatorScreen`；
普通用户没有创建 Global 段的权限时会退回 `Local\CameraEmulatorScreen`。
摄像头源运行在 Frame Server 的 session 0，**看不到用户会话的 Local 段**，于是一直显示占位图。

两种处理方式：

- 以管理员身份运行 `avatar_live.py`（创建 Global 段）；或
- 让部署启动器同时运行 `scripts/avatar_to_camera.py`：它读取 Global（读不到就退 Local）里的帧，
  以 10 fps 写成 `image.png`，摄像头即可显示动态画面，不需要提权。
  `features.avatar` 开启时启动器已默认带上这个桥接。

### 3. QQ 选了 CameraEmulator 仍显示实体镜头

这是已知未解决问题。实测在本机的一个可行绕过方式是**禁用实体摄像头**，让 QQ 没有别的选择：

```powershell
# 先查实例 ID
Get-PnpDevice -Class Camera
# 禁用（需要管理员）
Disable-PnpDevice -InstanceId 'USB\VID_xxxx&PID_xxxx&MI_00\...' -Confirm:$false
# 恢复
Enable-PnpDevice -InstanceId 'USB\VID_xxxx&PID_xxxx&MI_00\...' -Confirm:$false
```

禁用后实体摄像头对微信、会议等所有程序都不可用，用完记得恢复。
这属于人为规避，不改变“QQ 视频链路未通过验收”的结论。
