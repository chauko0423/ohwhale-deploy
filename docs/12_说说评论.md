# 说说评论：她能看见你写了什么

## 之前为什么看不见

`qq_power` 插件只有「发说说 / 列说说 / 点赞 / 评论 / 删说说」，
**没有读评论的能力**；QQ 也不会把空间评论推给她。所以你在她说说下面写的话，她完全不知道。

## 现在有两层能力

### 1）按需读（你让她去看）

对她说：

```
我评论了你最近那条说说，去看看
看看我评论了啥
```

她会先 `list` 拿到最近的说说和 `tid`，再 `comments` 读那条下面的评论，把
「谁 + 内容 + 时间」告诉你。

实现：`qq_qzone` 工具新增 `comments` 动作；`qzone.py` 新增 `QzoneClient.comments()`，
依次尝试 `emotion_cgi_msgdetail_v6` 和 `msglist`（带 commentlist）两个接口，哪个给数据用哪个。

### 2）主动看（定时巡检）

后台任务每隔 **N 分钟**看她最近 3 条说说的评论，发现**上次检查之后新出现的评论**，
就用她的人设生成 1~2 句私聊发给你（不是回复评论，是主动跟你说"有人在我这儿说话"）。

- 首次运行只建基线、不打扰（避免把历史评论当新评论刷屏）
- 同一评论用 `tid|uin|前60字` 做签名去重，最多保留最近 200 条签名
- 生成回复失败就退化成模板消息，保证通知不丢

## 配置

`config.json`：

```json
{
  "features": {
    "qzone_comment_poll": true
  },
  "qzone": {
    "comment_poll_minutes": 60
  }
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `features.qzone_comment_poll` | `true` | 是否启用定时巡检；关掉后只剩"按需读" |
| `qzone.comment_poll_minutes` | `60` | 巡检间隔（分钟），代码里夹在 10~1440 之间，改完重启 AstrBot 生效 |

> 间隔别设太短：空间接口有风控，10 分钟以内高频拉取容易触发验证或临时限制。
> 本机默认就是 **60 分钟**。

## 限制与排查

| 现象 | 先查 |
|---|---|
| 她说"读不出来" | 空间登录态是否还有效（`/power` 里会打印 cookie 与 g_tk 状态）；接口可能被风控 |
| 巡检不推消息 | 主人是否在**私聊**里跟她说过话（巡检需要记住私聊会话来主动发消息）；`features.qzone_comment_poll` 是否被关 |
| 一直重复推同一条 | 签名去重依赖 `uin + 内容前 60 字`，如果同一个人反复发同一句会被当成一条，这算预期行为 |
| 从不报告 | 首次启动只建基线；要等你在她说过之后**新写**评论才会报 |

## 看别人的说说、在别人的说说下评论

原来只能看/评论**自己的**说说：`list` 拉的是自己的 feed，`comment` 默认 `hostuin` 是自己——
所以她说「看不到你的说说」，在别人说说是评不上的。

现在补了两处：

| 动作 | 说明 |
|---|---|
| `qq_qzone(action="user", uin="对方QQ号")` | 拉**某个好友**的说说（`emotion_cgi_msglist_v6` + `hostuin`） |
| `qq_qzone(action="comment", tid="...", uin="对方QQ号", text="...")` | 评论**别人的**说说时把对方 uin 作为 `hostuin` 传下去 |
| `qq_qzone(action="friends")` | 好友动态列表现在带 `uin` 字段，模型可以直接拿来做上面两件事 |

用法示例：

```
你：去我空间看看我最近发的说说
她：（user 动作，uin=你的QQ号）
你：在第二条下面回我一句
她：（comment 动作，tid=刚拿到的，uin=你的QQ号）
```

前提：双方是好友、对方说说没有对你隐藏；空间接口有风控，偶发失败属正常。
